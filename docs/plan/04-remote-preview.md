# 2단계 첫 단위 — PR 하나의 커밋 하나를 이 컴퓨터에서 실행해 미리보기로 연다

> 한 줄 요지: **업무 화면의 PR 카드에서 Open Preview 를 누르면, Studio 서버가 그 PR 의 최신 커밋(전체 SHA)을 격리 폴더에 받아 `npm ci` 로 설치하고 앱을 켠 뒤, "실행 중 · PR 번호 · 커밋 · 주소" 를 보여 준다.** 실행기는 Studio 서버와 같은 컴퓨터에서 돌고, 나중에 Mac Pro 가 둘을 함께 맡는다. 결정 5 의 두 번째 성공 기준("PR 1건을 Mac Pro 에서 실행해 휴대전화에서 미리보기")의 소프트웨어 쪽을 이 단위가 만든다. 휴대전화 확인은 Mac Pro 에서만 할 수 있으므로 그 전까지 이 단위에는 **"실기기 미확인"** 이 붙는다.

## 1. 사람이 하는 일과 코드가 하는 일

| 누가 | 무엇을 | 어디서 |
|---|---|---|
| 사용자 | 미리보기를 돌릴 컴퓨터(나중에는 Mac Pro)의 `.env.local` 에 `PREVIEW_WORKDIR`(격리 폴더들의 부모, 절대 경로)를 적고 Studio 를 띄운다 | 그 컴퓨터 |
| 사용자 | 휴대전화로 보려면 그 컴퓨터와 휴대전화를 같은 사설망(Tailscale 류)에 넣고, `PREVIEW_BIND_HOST` 에 그 사설망 주소를 적는다 | 그 컴퓨터, 휴대전화 |
| 사용자 | 업무 화면의 PR 카드에서 Open Preview 를 누르고, 준비되면 Open 링크로 연다 | 브라우저 (노트북 · 휴대전화) |
| Studio | PR 의 **지금** 최신 커밋을 전체 SHA 로 고정하고, 대상 제한(복제본 금지)을 확인한다 | 서버 |
| Studio | 그 커밋의 코드를 GitHub 에서 **GET 으로** 받아(설치 토큰 사용) 새 격리 폴더에 푼다 | 서버 |
| Studio | 최소한의 환경변수만 준 자식 프로세스로 `npm ci` 와 `npm run dev`(없으면 `start`)를 돌리고, 주소가 응답하면 "실행 중" 으로 바꾼다 | 서버 |
| Studio | PR 에 새 커밋이 올라오면 실행 중인 미리보기를 "이전 버전" 으로 표시한다 | 서버 · 화면 |

## 2. 실행기가 어디에 있나 — 첫 버전은 Studio 서버 안이다

미리보기 실행기는 `PreviewRunner` 포트(`src/ports/preview-runner.ts`) 뒤의 어댑터다. 첫 버전의 어댑터(`src/adapters/preview/local/`)는 Studio 서버 프로세스 안에서 자식 프로세스로 PR 의 앱을 띄운다. Studio 와 실행기 사이의 원격 API 는 만들지 않았다. 그 이유는 Mac Pro 가 Studio 와 실행기를 **함께** 호스팅할 계획이라, 두 컴퓨터 사이의 통신이 첫 버전에는 필요 없기 때문이다. 개발 중에는 어느 컴퓨터든(클라우드 컨테이너 포함) 같은 코드로 돈다.

실행기는 **명시적 설정이 있을 때만** 켜진다. `PREVIEW_WORKDIR` 가 없으면 실행기는 "연결 안 됨" 상태이고, 화면은 Open Preview 버튼을 없애지 않고 **비활성**으로 둔 채 바로 옆에 이유 문장("미리보기 기기가 연결되지 않았다 — PREVIEW_WORKDIR 를 설정한 컴퓨터에서 Studio 를 띄운다.")을 보인다. 결정 7 의 "실행되지 않는 버튼을 두지 않는다" 를, 버튼을 숨기는 대신 "누를 수 없고 왜 그런지 보인다" 로 지킨 것이다. 화면 위쪽 띠에도 `Preview device: connected / not connected` 한 칸이 있다.

## 3. 설정

| 변수 | 뜻 | 기본값 |
|---|---|---|
| `PREVIEW_WORKDIR` | 격리 폴더들의 부모. 절대 경로. 미리보기마다 그 아래에 새 폴더를 만들고, 다음 미리보기를 열 때 지운다 | 없음 (없으면 연결 안 됨) |
| `PREVIEW_BIND_HOST` | 미리보기 앱에 `HOST` · `HOSTNAME` 으로 넘길 주소. 휴대전화로 보려면 사설망 주소 | `127.0.0.1` |
| `PREVIEW_PUBLIC_HOST` | 화면에 보일 주소의 호스트 (예: Mac Pro 의 사설망 이름) | `PREVIEW_BIND_HOST` (그것이 `0.0.0.0` · `::` 이면 `127.0.0.1`) |
| `PREVIEW_LOCAL_REPOS_DIR` | 코드를 GitHub 대신 이 폴더의 로컬 git 저장소(`<owner>/<name>`)에서 받는다. **시연과 시험용**이다 | 없음 |

공개 주소 · 터널은 만들지 않는다. 휴대전화 접근은 사설망을 전제로 한다.

고정 시연 데이터(fixture) 모드에서는 저장소가 GitHub 에 실재하지 않으므로 `PREVIEW_LOCAL_REPOS_DIR` 이 있어야 실행기가 켜진다. 시연 저장소는 `npm run preview:demo-repo -- <폴더>` 로 만든다. 이 명령은 시연 PR `demo-org/admin-console#12` 의 최신 커밋과 **글자 하나까지 같은 SHA** 의 커밋을 만든다(작성자 · 시각을 고정해 커밋 SHA 가 어느 컴퓨터에서나 같게 나온다).

## 4. 무엇을 실행하지 않나 — 대상 제한과 비밀

미리보기는 **신뢰할 수 없는 코드를 사용자 컴퓨터에서 돌리는 일**이다. 그래서 다음을 코드로 막는다.

1. **복제본(fork)에서 온 PR 은 미리보기로 실행하지 않는다.** 결정 10 과 같은 이유다 — 팀 밖의 누구나 복제본 PR 을 열 수 있다. 복제본인지 알 수 없으면 복제본으로 본다. 버튼은 비활성이고 이유가 보인다. (`src/domain/preview.ts` 의 `previewBlockOf`)
2. **커밋은 전체 SHA 로만 고정한다.** 짧은 SHA 는 둘 이상의 커밋을 가리킬 수 있어 받지 않는다. 실행 대상은 화면에서 보낸 값이 아니라 저장된 PR 의 **지금** 최신 커밋에서 서버가 다시 읽는다.
3. **자식 프로세스에 Studio 의 환경변수를 물려주지 않는다.** 허용 목록 방식이다 — `PATH` · `HOME`(Windows 는 `USERPROFILE` 등 필수 몇 개) · 언어 설정 · 임시 폴더, 그리고 실행할 때 `PORT` · `HOST` · `HOSTNAME` 만 준다. `GITHUB_*` · `DATABASE_URL` · `npm_config_*` 는 목록에 없으므로 넘어가지 않는다. 설치(`npm ci`) 단계에만 사내 프록시 변수(`HTTPS_PROXY` 등)를 더 준다 — 패키지를 받으려면 필요하기 때문이다. (`src/adapters/preview/local/child-env.ts`)
4. **코드를 받을 때 쓰는 토큰은 Studio 프로세스 밖으로 나가지 않는다.** 선택과 이유는 5절.
5. **실행 로그는 비밀처럼 보이는 값을 가려서 보인다.** GitHub 토큰 모양(`ghs_` · `ghp_` · `github_pat_` 등), `Authorization:` 헤더, 주소 안의 계정 정보를 `[가림]` 으로 바꾼다.

### 이 단위가 막지 못하는 것 (정직하게 적어 둔다)

- **이것은 격리 장치(샌드박스)가 아니다.** 자식 프로세스는 Studio 와 **같은 운영체제 사용자**로 돈다. 그래서 PR 의 코드는 그 사용자가 읽을 수 있는 파일(예: `.env.local`, 비밀 키 파일, `~/.ssh`)을 읽을 수 있다. 환경변수 허용 목록은 "물려주지 않는다" 이지 "읽지 못하게 한다" 가 아니다. 같은 저장소의 브랜치에서 온 PR(= 팀이 쓴 코드)만 실행하는 제한이 첫 버전의 방어선이다. Mac Pro 에서 운영할 때는 미리보기 전용 운영체제 사용자나 컨테이너로 돌리는 것이 다음 단계의 선택지다(`## 결정 필요` 로 올린다).
- **앱이 실제로 어느 주소에 묶일지는 그 앱이 정한다.** Studio 는 `HOST` · `HOSTNAME` 을 넘길 뿐이다. 이 변수를 따르지 않는 앱은 모든 주소(`0.0.0.0`)에 묶일 수 있다. 사설망 밖에서 닿지 않게 하는 것은 운영 컴퓨터의 방화벽 몫이다.
- **Studio 서버가 강제 종료되면(SIGKILL) 자식이 남을 수 있다.** 정상 종료 · Ctrl-C 에서는 자식 프로세스 묶음을 함께 끈다.

## 5. 코드를 어떻게 받나 — git 이 아니라 GitHub 의 tarball GET

PR 의 커밋을 받는 방법으로 git 을 쓰지 않고, GitHub REST 의 `GET /repos/{owner}/{repo}/tarball/{전체 SHA}` 를 기존 GET 관문(`src/adapters/github/rest/guarded-get.ts`)으로 보낸다.

- **GitHub 로 가는 요청이 여전히 GET 뿐이다.** git 의 HTTPS 받기는 내부적으로 `POST …/git-upload-pack` 을 보낸다. 읽기이긴 하지만, 이 저장소가 기계로 지키는 "GitHub 에는 GET 만(설치 토큰 교환 POST 하나 예외)" 경계(`tests/unit/architecture.test.ts`)를 흐리게 만든다. tarball 은 GET 한 번이다.
- **토큰이 명령줄 · 주소 · git 설정 파일 · 자식 프로세스 환경 어디에도 들어가지 않는다.** 토큰은 Studio 프로세스 안에서 `Authorization` 헤더로만 쓰인다. GitHub 는 tarball 요청을 `codeload.github.com` 의 서명된 일회용 주소로 돌려보내는데, 관문은 **그 한 곳으로만** 따라가고, 따라갈 때는 `Authorization` 헤더를 **떼고** 보낸다. 받는 크기에는 상한(200MB)이 있다.
- 받은 묶음은 운영체제의 `tar` 로 새 격리 폴더에 푼다. GNU tar 와 bsdtar(macOS · Windows 10 이상)는 `..` 이 든 이름을 기본으로 거부한다.
- 두 GitHub 출처(App 과 조직 토큰, 결정 12)를 함께 쓰면, App 의 설치 토큰으로 먼저 받고 거절(403 · 404)되면 조직 토큰으로 한 번 더 받는다.

시연 · 시험용 로컬 저장소(`PREVIEW_LOCAL_REPOS_DIR`)에서는 `git archive <전체 SHA>` 로 같은 묶음을 만든다. 네트워크를 쓰지 않는다.

## 6. 실행 규칙 (첫 버전)

1. Node 프로젝트만 지원한다. `package.json` 과 lockfile(`package-lock.json` 또는 `npm-shrinkwrap.json`)이 있어야 한다. lockfile 이 없으면 설치하지 않고 이유를 보인다 — `npm ci` 는 lockfile 그대로만 설치해 "무엇을 설치했는지" 가 커밋에 고정되기 때문이다.
2. 설치는 `npm ci --no-audit --no-fund`, 시작은 `package.json` 에 `dev` 스크립트가 있으면 `npm run dev`, 없으면 `npm run start` 다. 둘 다 없으면 이유를 보인다. 포트는 비어 있는 것을 골라 `PORT` 로 넘긴다.
3. 준비 확인은 그 포트에 HTTP 요청을 보내 **어떤 응답이든** 오는 것이다. 설치 10분 · 시작 3분의 상한이 있고, 넘으면 끄고 실패 이유와 로그 꼬리(최근 40줄)를 보인다.
4. **동시 미리보기는 1개다(계약 §6).** 새로 열면 이전 것을 끄고, 새 미리보기 칸에 "이전 미리보기(저장소#번호 · 커밋)를 종료했다" 를 보인다.
5. 미리보기 상태는 **서버 메모리**에 둔다. 자식 프로세스의 수명이 서버의 수명과 같으므로 저장할 이유가 없다. PostgreSQL 스키마는 바꾸지 않았다.

## 7. 신선도 (계약 §6)

미리보기 기록은 (저장소 숫자 ID, PR 번호, 전체 커밋 SHA) 를 갖는다. PR 의 최신 커밋과 SHA 가 다르면 미리보기 칸에 **"이전 버전 — 이 미리보기는 커밋 A 이고, PR 의 최신 커밋은 B 이다. 검토 근거로 쓰지 않는다."** 를 보인다. 판정은 1단계의 `src/domain/freshness.ts` 를 그대로 쓴다. 사용자가 Open Preview 를 다시 누르면 최신 커밋으로 새로 연다.

## 8. 범위

| 들어가는 것 | 들어가지 않는 것 |
|---|---|
| `PreviewRunner` 포트와 두 어댑터(연결 안 됨 · 이 컴퓨터) | Studio 와 실행기 사이의 원격 API |
| 대상 제한(복제본 · 짧은 SHA) 과 신선도 판정 | 공개 주소 · 터널 · 미리보기 주소의 로그인 |
| 업무 화면 PR 카드의 Open Preview · Open · Stop Preview, 위쪽 띠의 기기 상태 한 칸 | Node 외의 프로젝트(Python · 정적 사이트 등), 여러 개의 동시 미리보기 |
| GitHub tarball GET 으로 코드 받기, 로컬 저장소로 받기(시연 · 시험) | 샌드박스 격리(별도 사용자 · 컨테이너) |
| 설치 · 시작 상한, 로그 꼬리와 비밀 가림, 서버 종료 시 자식 정리 | 미리보기 기록의 영구 저장(PostgreSQL) |
| 시연 저장소 만들기 명령(`npm run preview:demo-repo`) | Sync 속도 개선 |

## 9. 통과 기준

1. `PREVIEW_WORKDIR` 가 없으면 업무 화면의 모든 Open Preview 버튼이 비활성이고, 바로 옆에 연결되지 않은 이유가 보인다. 위쪽 띠에 `Preview device: not connected` 가 보인다. 첫 화면에서 출발하는 e2e 가 확인한다.
2. 복제본에서 온 PR 과 전체 SHA 가 아닌 PR 은 실행기가 연결돼 있어도 버튼이 비활성이고 이유가 보인다. 유스케이스도 같은 요청을 거절한다(오래된 화면에서 누른 경우). 단위 시험이 확인한다.
3. 연결된 실행기로 Open Preview 를 누르면 "Running · PR #n · 커밋 앞 7자리 · 주소" 와 Open 링크가 나타나고, 그 주소가 실제로 PR 커밋의 앱 화면을 돌려준다. 이 클라우드 컨테이너에서 실제 `npm ci` 와 실제 프로세스로 e2e 와 통합 시험이 확인한다.
4. 다른 PR 의 미리보기를 열면 이전 것이 꺼지고(포트가 닫힌다) 새 칸에 종료 알림이 보인다. Stop Preview 는 프로세스를 끈다. 통합 시험이 확인한다.
5. PR 에 새 커밋이 오면 실행 중인 미리보기가 "이전 버전" 으로 표시된다. 통합 시험이 확인한다.
6. lockfile 이 없거나, 시작 스크립트가 없거나, 시작 상한을 넘으면 실패 이유와 로그 꼬리가 보인다. 통합 시험이 확인한다.
7. 자식 프로세스의 환경에 `GITHUB_*` · `DATABASE_URL` 이 없다(실제 자식 프로세스가 자기 환경을 응답으로 돌려주게 해서 확인한다). 로그 꼬리에서 토큰 모양이 가려진다.
8. GitHub 에서 받는 경로는 GET 만 보내고, `codeload.github.com` 으로만 따라가며, 따라갈 때 `Authorization` 을 싣지 않는다. 가짜 GitHub 응답으로 시험한다. **실제 GitHub 로는 아직 돌려 보지 않았다** — 비밀 키가 있는 사용자 컴퓨터에서 처음 확인한다.
9. `child_process` 를 import 할 수 있는 곳은 `src/adapters/preview/local/` 뿐이고, fetch 를 부르는 곳은 여전히 두 파일뿐이다. 아키텍처 시험이 확인한다.

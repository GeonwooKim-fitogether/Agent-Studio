# 1단계 두 번째 단위 — PostgreSQL 저장, 연결 되돌리기, 복제본 PR 차단

> 한 줄 요지: **업무 · 연결 · 검토 기록이 서버를 다시 켜도 남도록 PostgreSQL 에 저장하고, 그와 함께 사람이 잘못 연결한 PR 을 되돌리는 Unlink 와 복제본(fork) PR 을 자동 연결에서 빼는 규칙을 넣는다.** 결정 9 와 결정 10 을 이 단위에서 코드로 옮긴다.

첫 단위([`01-pr-collection.md`](./01-pr-collection.md))의 구조를 그대로 쓴다. 저장 포트(`StudioStore`)는 처음부터 비동기로 만들어 두었으므로, PostgreSQL 어댑터는 같은 인터페이스를 구현해 조립부에서 갈아 끼운다. 대상 환경은 **local** 과 CI 의 일회용 데이터베이스뿐이다(환경 분리 규칙). development · staging · production 은 아직 없다.

## 1. 왜 세 가지를 한 단위로 묶었나

- **저장이 영구해지면 잘못된 연결도 영구해진다.** 지금은 서버를 다시 켜면 실수가 사라지지만, 저장을 옮기는 순간부터는 되돌릴 방법이 있어야 한다(결정 9).
- **복제본 차단은 자동 연결 규칙 한 줄이다.** 진짜 GitHub 를 붙이기 전에 막아야 하는 구멍이고, 도메인 규칙과 fixture 한 건으로 검증된다(결정 10).

## 2. 범위

| 들어가는 것 | 들어가지 않는 것 |
|---|---|
| `StudioStore` 의 PostgreSQL 구현(`pg` 드라이버), 연결 · 업무 생성 · 연결 해제를 트랜잭션으로 | ORM, 쿼리 빌더 |
| 첫 마이그레이션 `db/migrations/<UTC 시각>_initial_schema.sql`, 적용 이력 표, 적용 명령 `npm run db:migrate` | development · staging · production 적용 |
| 조립부: `DATABASE_URL` 이 있으면 PostgreSQL, 없으면 메모리. 화면 상단이 어느 저장인지 표시 | 진짜 GitHub 연결(GitHub App 설치 · 토큰 발급) |
| 같은 저장 계약 테스트를 메모리와 PostgreSQL 양쪽에 돌린다 | 닫힌 · 병합된 PR 을 Inbox 에서 숨기기 (진짜 GitHub 연결 단위에서) |
| Unlink: 업무 화면의 PR 카드에서 연결을 풀어 PR 을 Inbox 로 돌려보낸다. 사람이 푼 PR 은 표식으로 다시 자동 연결되지 않는다 | 업무 삭제, 업무 이름 바꾸기 |
| 복제본 규칙: PR 의 브랜치가 다른 저장소에 있거나 알 수 없으면 표식이 있어도 Inbox | 쓰기 권한자 판정 |
| CI 에 PostgreSQL 서비스를 붙여 빈 데이터베이스에 전체 마이그레이션을 적용하고 테스트 | |

## 3. 통과 기준

1. **빈 데이터베이스에 마이그레이션을 처음부터 적용할 수 있다.** 같은 명령을 두 번 실행해도 두 번째는 아무것도 바꾸지 않는다. 적용 명령은 `APP_ENV` 가 `local` 또는 `test` 가 아니면 실행을 거부한다.
2. **저장 계약 테스트가 메모리와 PostgreSQL 양쪽에서 똑같이 통과한다.** 복사본 규칙, 한 PR 에 연결 하나, 업무 생성과 연결의 원자성, 연결 해제가 포함된다.
3. **서버를 다시 켜도 사람이 만든 연결 · 업무 · 해제가 남는다** (PostgreSQL 모드). e2e 또는 통합 테스트가 재시작을 넘어 확인한다.
4. **Unlink** 를 누르면 PR 이 그 업무에서 사라지고 Inbox 에 "사람이 연결을 풀었다" 는 이유와 함께 다시 나타난다. 그 PR 에 표식이 있어도 다음 Sync 에서 자동으로 붙지 않는다. Inbox 에서 사람이 다시 연결하면 정상적으로 연결된다.
5. **복제본에서 온 PR** 은 같은 프로젝트 업무의 표식이 있어도 Inbox 로 가고, 이유가 화면에 보인다. 복제본 여부를 알 수 없는 PR 도 같다. REST 어댑터는 PR 의 브랜치가 속한 저장소 ID 를 읽는다.
6. 첫 단위의 테스트(단위 102건, e2e 6건)가 계속 통과한다. 메모리 모드는 그대로 동작한다.
7. 데이터베이스 비밀번호 같은 자격증명은 저장소 · 로그 · 화면에 싣지 않는다. 로컬 예시값은 `.env.example` 의 것만 쓴다.
